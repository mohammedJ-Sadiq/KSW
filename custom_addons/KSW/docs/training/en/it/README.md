For the **IT Team** — the people who receive, triage and resolve support
tickets, and who own the IT asset register.

## How the app is laid out

| Menu | Who sees it |
|---|---|
| **My Tickets** | Everyone — your own tickets, like any employee |
| **All Tickets** | IT Team — the queue, as a kanban board |
| **Ticket History** | IT Team — every closed ticket |
| **Reporting** | IT Team — volume, mix and resolution time |
| **Assets → Assets / Assignments / Maintenance** | IT Team only |
| **Configuration → Ticket Stages / Ticket Categories / Asset Categories** | IT Team only |

## The golden rules

- **Two kinds of ticket, and the kind is permanent.** An **Incident** is
  something broken (`INC…`); a **Service Request** is something needed
  (`REQ…`). It sets the ticket number and cannot be changed afterwards.
- **The ticket is the record.** A phone call that isn't written on the ticket
  did not happen. Post with **External** to talk to the employee, **Note** for
  internal record-keeping.
- **Only the IT Team moves a ticket.** Stage, assignee and the blocked/ready
  marker are yours; employees can see them but never set them.
- **Assets are IT-only, and custody is a workflow.** Never type into
  **Assigned To** — hand over and take back through **Assign to Employee** and
  **Return**, so the history stays true.
- **Close tickets when the work ends.** Resolution time is measured from
  creation to closing, and every report is built on it.
